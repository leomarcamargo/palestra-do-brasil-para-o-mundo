# Checklist de LinkedIn e GitHub

Use esta lista para revisar seus perfis. Marque o que já fez e volte aqui a cada semestre.

[Voltar ao início](README.md)

> Currículo diz. LinkedIn mostra. GitHub prova.

## LinkedIn

### Perfil

- [ ] **Foto** simples, rosto visível, fundo neutro. Não precisa ser de estúdio.
- [ ] **Banner** com uma frase sobre o que você faz, ou uma imagem de um projeto seu.
- [ ] **URL personalizada**: `linkedin.com/in/seunome`. Leva 30 segundos e fica bem no currículo.
- [ ] **Localização** definida (cidade e país).

### Headline: a linha mais importante

É ela que aparece na busca do recrutador. Use a fórmula:

```
[o que você é] · [tecnologias] · [o que constrói ou busca]
```

| Evite | Prefira |
|---|---|
| Estudante de SI em busca de oportunidades | Information Systems student · Java, SQL, Git · I build web apps |
| Apaixonado por tecnologia | Software Development student · Python, SQL · learning data analysis |

- [ ] Minha headline segue a fórmula.

### Seção "About"

Três parágrafos curtos, em primeira pessoa:

1. **Quem você é agora:** curso, período, área de interesse.
2. **O que já construiu:** um exemplo concreto, com link.
3. **O que procura:** tipo de vaga, modelo de trabalho (remoto, híbrido).

- [ ] Meu "About" tem os três parágrafos.
- [ ] Li em voz alta e soa como uma pessoa, não como uma descrição de vaga.

### Conteúdo

- [ ] **Experiência e projetos** com o que você fez, a tecnologia e o resultado.
- [ ] **Featured (Destaques)** com seu melhor projeto, artigo ou vídeo.
- [ ] **Skills**: de 15 a 25, escolhidas a partir das vagas que você quer.
- [ ] **Recomendações** de professores, colegas de projeto ou orientadores.
- [ ] **Perfil em inglês** quando você já estiver se candidatando para fora. O LinkedIn permite ter um perfil em português e outro em inglês.

### Regra de ouro

- [ ] Nome, cargos, empresas e datas são **iguais** no LinkedIn e no currículo. Diferença gera desconfiança.

### Atividade

- [ ] Compartilho, de vez em quando, algo que aprendi ou construí. Não precisa ser genial; precisa existir.

### Mensagem de abordagem (5 linhas)

Quando quiser falar com alguém de uma empresa, não peça emprego. Peça uma opinião:

```
Hi Ana, I read your post about APIs in Java.
I'm a student in Brazil, and I'm building a small API too.
What was the hardest part for you?
Thank you! Your post helped me a lot.
```

1. **Contexto específico:** algo que a pessoa fez.
2. **Prova curta:** o que você está fazendo.
3. **Pergunta pequena:** fácil de responder.
4. **Saída sem cobrança:** a pessoa pode não responder.

## GitHub

### Perfil

- [ ] **Foto, nome e bio curta** em inglês.
- [ ] **README de perfil** (repositório com o seu nome de usuário) dizendo quem você é, sua stack e 2 ou 3 projetos em destaque.
- [ ] **Projetos fixados (pinned)**: os 2 ou 3 melhores, não os mais recentes.

> Três bons projetos fixados valem mais que trinta tutoriais.

### Cada projeto fixado

- [ ] Tem um **README** que responde:
  - [ ] Que **problema** o projeto resolve.
  - [ ] **Como rodar** o projeto, passo a passo.
  - [ ] Quais **decisões técnicas** você tomou e por quê.
  - [ ] Como rodar os **testes**.
  - [ ] Quais são as **limitações** e o que você faria diferente.
  - [ ] **How AI was used**: onde a IA ajudou, onde errou e o que você reescreveu.
- [ ] **Roda em outra máquina**, não só na sua.
- [ ] **Não tem senha, token ou arquivo `.env`** no repositório. Se tiver, apague e troque a senha.
- [ ] **Commits** com mensagens claras, em inglês.
- [ ] Se seguiu um tutorial, **diga isso** e mostre o que você acrescentou.

### Modelo simples de README

```markdown
# Project name

One sentence about what it does and for whom.

## Why
The problem it solves.

## Features
- Main feature 1
- Main feature 2

## Tech stack
Java, Spring Boot, PostgreSQL, Docker

## How to run
Steps to run it on your computer.

## Tests
How to run the tests.

## How AI was used
Where AI helped, where it was wrong, and what I changed.

## What I learned
Decisions, problems, and what I would do differently.
```

### Ideias de projeto que chamam mais atenção que tutoriais

- Um sistema para uma necessidade real: uma ONG, o centro acadêmico, um pequeno negócio da família.
- Uma contribuição para um projeto open source. Comece por documentação e issues marcadas como "good first issue".
- Uma API completa, com autenticação, banco de dados, testes e deploy.
- Um projeto que usa IA de forma responsável, explicando limites e custos.

## Experiência comprovada não é só carteira assinada

Tudo isto conta como experiência, se for bem descrito:

- Projeto com usuário real
- Contribuição aceita em open source
- Iniciação científica
- Projeto de extensão
- Monitoria
- Freela pequeno entregue
